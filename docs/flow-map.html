0 · The three doors — one orchestrator

All three invocations construct and drive the same root_agent. There is no second code path.

adk web agents / adk run …

  1. ADK imports agents/lead_profile_agent/__init__.py → from . import agent
  2. Importing agent.py runs _load_dotenv_if_present() — agent-dir .env first, then repo root
  3. build_root_agent() reads LQABR_ORCHESTRATOR (default deterministic; llm = opt-in; anything else raises)
  4. root_agent = DeterministicLeadProfileAgent(…) from pipeline_agent.py

lead-profile-agent (headless / Cloud Run Job)

  1. pyproject.toml [project.scripts] → agent.py:main()
  2. run_headless() builds an ADK InMemoryRunner over the same root_agent
  3. Sends the fixed prompt "run the pipeline …", streams events, maps session state → exit code 0 / 2 / 3

Same orchestrator in dev and prod — no drift possible.

1 · The run, start to end

Turn begins — ADK Runner delivers the operator message

pipeline_agent.py · _run_async_impl()

Binds RunContext(run_id = ADK invocation_id, uses_model=False) and the Observability bundle — so every log line of this run correlates with the adk web event view. Emits container_up (memory/CPU snapshot) and agent_invoked.

lib/obs/context.pylib/obs/loggers.py
operator text

Command parsing — written rules, never a guess

pipeline_agent.py · parse_command()

run the pipeline · … limit 5 · dry run · lookup E1042 / lookup email a@b.c · anything unrecognised → usage help. The parsed command is logged (operator_command) so the interpretation is itself auditable.

action = run

STEP 1+2 — load & structurally validate the three CSVs

src/load_csv.py · load_csvs()

Reads employees_with_company_sample.csv, employee_contacts_5234.csv, companies_clean_734.csv (UTF-8-sig, BOM/CRLF-safe). Asserts required columns per file. Unit-suffixed columns get deterministic aliasing: the real feed's Annual_Revenue (₹) matches the contract's Annual_Revenue (M) by exactly-one-prefix rule; ambiguity halts; every alias is logged (column_alias_applied).

HALT — structural feed failure. Missing file or column raises CsvStructureError naming the exact file + column. Agent yields “HALTED — … No lead was pushed”, state feed_loaded=false, headless exit code 2. Nothing downstream runs.
RawFeed (3 in-memory row lists)

STEP 3 — build the decision-maker profile list, in memory only

src/build_profile.py · build_profiles()

Indexes contacts by (Employee_ID, Company_ID) and companies by Company_ID — duplicate source rows are counted and logged, never silently overwritten. Keeps rows where Decision_Maker_Flag == "yes" (the single source of truth in schema.py). Both joins resolve → LeadProfile (9-field contract); either missing → UnresolvedLead. Counts reconcile: decision_makers_seen = profiles + unresolved + duplicates.

lqabr_mcp/hubspot/schema.py · LeadProfile
unresolved leads persisted — never dropped

Unresolved evidence written to disk

lqabr_mcp/hubspot/crm.py · record_unresolved()

→ errors/unresolved.jsonl with run_id + reason per lead. (On Cloud Run, errors/ lives on the mounted GCS volume.)

EXIT — dry run. If the operator said dry run, the agent reports the counts and stops here: no HubSpot call, no token minted. This is how 263 was confirmed before any write.
list[LeadProfile] (limit applied if requested)

STEP 4 — the loop: one in-process MCP call per lead

src/call_mcp.py · push_profiles()

For each profile: mint a unique lead_ref_id (lib/obs/context.py), then call upsert_lead_profiles() — a Python call, not a network hop. Tallies the three-way outcome (pushed / failed_record / failed_transport) into RunSummary; a circuit breaker (failures.py) halts the run after N consecutive transport failures so an outage never masquerades as N bad leads.

per lead — in-process

STEP 5 — TOOL 1: upsert_lead_profiles (the only writer)

lqabr_mcp/hubspot/crm.pylqabr_mcp/hubspot/schema.py

Per lead: (1) normalise-then-validate (baseline, no network) → (2) Company search-by-company_id → PATCH/POST → (3) Contact search-by-employee_id → PATCH/POST → (4) associate (v4 default). Company before Contact, so a rejection can never orphan a Contact in a lead pipeline. Create+update = one idempotent upsert. Duplicate dedup-keys in HubSpot are detected (search limit 2) and logged.

before EVERY HubSpot HTTP call

STEP A — M2M auth: get_hubspot_token()

lqabr_mcp/hubspot/auth.pylib/secrets.py

TokenCache → TokenProvider (private_app interim · refresh_token target — mode has no default, unset is an error). The credential itself is resolved at runtime from Google Secret Manager (lqabr-hubspot-access-token) under ADC / workload identity — audit-logged, value redacted, cached 15 min, never on disk or in os.environ.

HALT — systemic failure. Auth/secret misconfiguration raises SystemicFailure: the run stops, remaining leads are reported not_attempted, and no per-lead error record is written — one missing credential is never “263 bad leads”. Headless exit 2.
RETRY ladder (per HTTP call) — crm.py · HubSpotHttp.request(): transport exceptions retried with backoff · 429/5xx retried honouring Retry-After · 401/403 retried once with a forced token refresh. Exhausted → transport_failures.jsonl. HubSpot 400/409/422 → schema_mismatch.jsonl with lead_ref_id + stage_reached + any ids already written. The run continues either way.
RunSummary

Turn ends — summary event + state delta

pipeline_agent.py

Final event: pushed / failed_record / failed_transport / not_attempted / unresolved / run_id — “No lead was dropped: every non-pushed lead is on file with a reason.” Session state (pushed, failed, halted) travels as EventActions.state_delta. agent_complete + container_down close the four logs. Headless exit: 0 clean · 2 structural/systemic halt · 3 completed with per-record failures.

2 · STEP 6 — the read path (not part of the pipeline)

Operator: lookup E1042

  1. pipeline_agent.py · _do_lookup() → crm.py · get_lead_profile()
  2. Contact search by employee_id (or the custom email_id property) → associated Company → 9-field profile + contact_hs_id/company_hs_id
  3. company_resolved=false + warnings[] whenever the company half could not be read — never a silently half-empty profile

Other agents (email / voice / scheduler)

  1. In the same process: from lqabr_mcp.hubspot import get_lead_profile
  2. Cross-process / cross-language: lqabr_mcp/server.py serves the same two functions over the MCP protocol (stdio / streamable-http) for ADK MCPToolset

Two front doors, one implementation — the write path cannot fork.

3 · Every file: where it runs, and why it exists

Agent package — agents/lead_profile_agent/

fileexecutes atwhy it needs to exist
__init__.pyimport time (adk discovery) from . import agent is the hook adk run/web use to find root_agent. Load-bearing, not decorative.
agent.pyimport time + headless entry The single place the orchestrator is chosen (LQABR_ORCHESTRATOR) and the headless door (run_headless/main). Loads .env before the choice is read; guarantees dev and prod drive the identical agent.
pipeline_agent.pyevery turn (default) The deterministic orchestrator — Steps 1–5 as one agentic run with zero model calls. Exists so §7.4 holds, the pipeline has no LLM outage mode, and every branch is a written, testable rule.
llm_agent.pyonly when LQABR_ORCHESTRATOR=llm The opt-in conversational console over the same tools — free-form phrasing, failure triage in plain language. Its failure breaks a chat, never ingestion.
tools.pyLLM variant tool calls Wraps the step functions as JSON-schema-able ADK tools with preconditions (next_step refusals) and a process-local run store, so a model can orchestrate but never see, skip, or reorder the data work.
callbacks.pyLLM variant lifecycle Bridges ADK callbacks to the four logs: run_id = invocation id, every tool choice audited, after_model feeds the tokens log — the FR’s “tokens wherever a model runs”.
model.pyfirst model call (LLM variant) SecretBackedLiteLlm: resolves the API key lazily from Secret Manager, passes it in-memory to LiteLLM — never into os.environ, never at import.
container_definition.pyread, not executed Machine-readable architecture: in-process MCP dependency, required env, secret names, orchestrator default. Asserted by tests, so the declared design can’t drift from reality.
src/load_csv.pyStep 1+2 The feed boundary: fail loudly on structural problems before any processing, name file+column exactly, alias unit-suffixed headers deterministically. Per-file path overrides are the future BigQuery swap point.
src/build_profile.pyStep 3 The join+filter that produces the in-memory lead list — the FR’s “no JSON artifact” rule lives here. Reports (never hides) duplicates and unresolved rows; counts must reconcile.
src/call_mcp.pyStep 4 The per-lead loop and the run’s bookkeeping: lead_ref_id minting, three-way failure tally, circuit breaker. Keeps “driving the pipeline” separate from “talking to HubSpot”.

Central MCP — lqabr_mcp/ shared with email / voice / gateway

fileexecutes atwhy it needs to exist
hubspot/schema.pySteps 3 & 5 The 9-field data contract as code — field names and HubSpot property names (incl. custom email_id), payload mapping, baseline validation. One definition every agent shares; renaming anything here breaks the platform on purpose.
hubspot/crm.pySteps 5 & 6 The only two tools: upsert_lead_profiles (sole writer: search→upsert→associate, retry ladder, error-file routing) and get_lead_profile (sole reader). One HTTP transport = one place to audit-log and one place to mock.
hubspot/auth.pyStep A (every HubSpot call) M2M token utility behind one TokenProvider interface — interim private_app and target refresh_token swap by config, no call-site change. No default mode: the non-compliant path must be chosen deliberately.
hubspot/failures.pySteps 4–5 error paths The failure taxonomy (record / transport / systemic) + circuit breaker. Exists so “263 leads failed” can never again mean “one env var was missing” or “HubSpot was down”.
server.pyseparate process (other agents) The same two tools over the real MCP protocol — a language-agnostic contract for the other three agents that cannot drift, because it calls the identical functions.
__init__.pyimport time Named lqabr_mcp, not mcp — a top-level mcp package shadows the official MCP SDK this repo depends on.
