Never lose an outcome — every failure path has a destination
⛔ Step 3 stop — not dialable from get_lead() not-found · no phone · opted out · not-qualified · in-flight — reason logged (WARNING, not ERROR), lead untouched, nothing dialed.
▲ Pre-dial failure — claim released from handle_new_lead() any raise out of place_call() → _release_claim() writes FAILED. A lead is never stranded on a blocking INITIATED.
▲ Model failure — deterministic fallback from summarise_report() outcome still produced, marked classified_by=fallback; Step 8 always runs — a call's record is never lost to an LLM outage.
Unresolved contact — logged, not written from handle_call_report() no object_id in the report → outcome + summary land on process_log at ERROR; nothing is guessed into the CRM.
Duplicate report — skipped idempotency pre-check voice_status already terminal → status duplicate, Step 8 skipped; probability can never be double-applied by a redelivery.
⛔ Partial write — surfaced from record_call_outcome() failures listed in failures[], status partial — "status written, probability not" is never disguised as success.
Observability — every box above emits here.  three JSON streams → stdout (Cloud Logging): system (startup/config) · process (per-step decisions: started / ok / stopped / degraded / skipped / error) · audit (every MCP + Vapi call: endpoint, status, attempt, ms, credential name) — one correlation_id spans both requests of a call's life · Step 7 logs model, input/output tokens, latency per invocation.
