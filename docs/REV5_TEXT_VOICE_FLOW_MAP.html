Observability — three streams, one correlation id

system_log

Is the service itself healthy?

Startup/shutdown, revision, config problems. Carries no lead identity on purpose.

process_log

Where did this call get stuck, and what did the model decide at what cost?

Every step: started → ok/stopped/error/degraded with duration_ms; plus model, input/output tokens and latency at step 7.

audit_log

Did this request actually go out, and what came back?

Every inbound (signature scheme, status) and outbound (credential name, status, attempt) HTTP call. Token values are never logged.

jsonPayload.correlation_id="<id>"                          # one lead, every step
jsonPayload.log_stream="audit"   AND jsonPayload.status_code>=400
jsonPayload.log_stream="process" AND jsonPayload.step="step7.summarise_report"
jsonPayload.log_stream="process" AND jsonPayload.status="degraded"

Deviations from Rev 5

Places the spec could not be implemented literally. None silently dropped.

HubSpot rejects self-minted JWTs

Rev 5 steps 3 and 8 send Authorization: Bearer <jwt> to HubSpot. The CRM v3 API accepts only HubSpot-issued credentials; a self-signed JWT returns 401, and the token endpoint has no jwt-bearer grant. Now uses the private-app token from Secret Manager per your call — the "no static tokens" requirement is unmet on this leg and tracked separately.

Step 1 could not fire as written

The spec triggers on email_status = "clicked". The real lqabr_email_status enum has no CLICKED option — only PENDING / SENT / DELIVERED / OPENED / FAILED / BOUNCED. Eligibility is now OPENED, config-driven via LQABR_TEXT_VOICE_ELIGIBLE_EMAIL_STATUS.

Two Data-Fields entries are UI labels, not API names

voice_status and email_status both return propertiesNotFound. The real properties are lqabr_voice_status and lqabr_email_status. Verified against portal 246777241 via the properties API.

Step 5 is owned by another developer

crm/hubspot.py is untouched. text_voice.py carries a clearly-marked temporary _MCPAdapter that satisfies the same contract and defers automatically once the real module-level tools land. Full spec in REV5_MCP_TOOL_CONTRACT.md.
